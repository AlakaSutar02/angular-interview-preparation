To understand how Angular boots up (bootstraps) your application, it helps to think of it as a **relay race**.
The browser starts with a blank HTML file, passes the baton to JavaScript, and JavaScript hands it off to Angular to bring your components to life.

Here is the step-by-step breakdown of how this happens in modern Angular (v17 through v21+), which uses the streamlined **Standalone** architecture.

---

### Step 1: The Browser Loads `index.html`

When a user visits your app, the server serves a single, mostly empty HTML file.

Inside this file, you will find two crucial things:

1. A custom placeholder tag (the root component selector), usually `<app-root></app-root>`.
2. A `<script>` tag linking to your compiled JavaScript bundle (generated by the build tool).

At this exact moment, the user just sees a blank screen or a "Loading..." message because the browser doesn't know what `<app-root>` means yet.

---

### Step 2: The Gateway (`main.ts`) Fires Up

The browser executes the JavaScript bundle, which immediately points to the entry file of your application: `main.ts`.

In modern Angular, this file is incredibly lightweight. Its sole job is to call a function named `bootstrapApplication()`.

```typescript
// main.ts
import { bootstrapApplication } from "@angular/platform-browser";
import { AppComponent } from "./app/app.component";
import { appConfig } from "./app/app.config";

bootstrapApplication(AppComponent, appConfig).catch((err) =>
  console.error(err),
);
```

This function tells Angular: _"Hey, start the engine using `AppComponent` as the absolute root of the UI, and apply these global configurations."_

---

### Step 3: Setting Up Global Configurations (`app.config.ts`)

Before Angular paints anything on the screen, it reads the `appConfig` object passed into the bootstrap function. This is where global configurations are injected into the application, such as:

- **Routing:** Directing users to different pages based on the URL.
- **HTTP Client:** Enabling the app to talk to backend APIs.
- **Animations / Zoneless features:** Configuring how the app handles changes.

---

### Step 4: Activating the Root Component (`app.component.ts`)

Once configuration is ready, Angular looks at `AppComponent`. It reads the component's metadata (the `@Component` decorator) to figure out three things:

1. **The Selector:** It matches `selector: 'app-root'` with the `<app-root>` tag waiting in `index.html`.
2. **The Template:** It grabs the HTML structure of your main component.
3. **The Styles:** It grabs the CSS to make it look right.

---

### Step 5: Pinpoint Rendering and Change Detection

Angular replaces the empty `<app-root></app-root>` tags in the browser's DOM with your actual app template.

- **In modern Angular (v17-v21+):** Instead of checking the entire page for updates constantly, Angular initializes its **Signals** engine during this phase. It targets the exact spots on the page that require rendering, making the initial load lightning fast.

The relay race is complete: your Angular app is officially alive and interactive!

---

### Summary Workflow

```
[index.html loads] ➔ [main.ts executes bootstrapApplication()] ➔ [Global configs applied] ➔ [AppComponent matches <app-root>] ➔ [App becomes interactive]

```
